# 第4回 — CSVをBlobに保存して、表とグラフで見る

今回は、CSVファイルをアプリからBlobに保存してみます。保存した内容を読み直し、表とグラフで見ていきましょう。
ページを開き直してもファイルが残っているか、別のCSVを入れると何が変わるかも試します。

使うのは、講師が用意した自分専用のアプリです。参加者はブラウザーで操作し、環境の構築や最後のAzureリソースの削除は講師が担当します。

対象: Azureを初めて操作する人。第1〜3回のリソースは不要  
基本課題: **45〜60分＋予備15分**。講師の環境準備・リソース削除の待ち時間は別枠  
操作: 用意された専用アプリとブラウザー。Docker、プログラミング、Storageの鍵は不要  
更新日: 2026-10-12 ／ [実施・画面の確認状況](run-through.md)

**配布前の確認（制作版）:** Azureに用意したアプリで、保存・表とグラフの表示・開き直し・削除まで試しています。
Portalだけでの環境構築と全操作、初学者による確認はまだ終わっていません。
画面写真は検証時に撮影したものです。その後に案内文を見直しているため、一部の文章は現在のアプリと異なります。

> **使うのは配布した架空CSVだけです。** 業務データ、個人情報、秘密情報はアップロードしないでください。
> 非公開のBlobに、アプリのマネージドIDで読み書きします。Storageの鍵やSASをブラウザーに渡す必要はありません。
> この環境はIP制限付きの学習用です。本番では、利用者のログインやデータの分離も別に設計します。

## 今日の流れと覚える言葉

![Microsoft公式アイコンを使用した、ブラウザーからContainer Appsを通して非公開Blobへ保存・再読込する説明図](assets/upload-flow.png)

図は今回の処理の流れを描いたものです。Portalの画面や、お客様の本番環境ではありません。
保存も読み込みもContainer Appsを通ります。ブラウザーがBlobのURLに直接書き込むのではなく、アプリが受け取って保存します。

| 用語 | この実習での意味 |
| --- | --- |
| Container App | ファイルを受け付け、検査し、Blobへ保存・読み込みするアプリ |
| ストレージアカウント | Storageサービスをまとめる管理単位 |
| Blobコンテナー | Blobをまとめる単位。今回の名前は`uploads` |
| Blob | 保存された1つのファイル。今回のCSVが該当する |
| マネージドID | アプリがAzureへ接続するためのID。人のログインIDとは別 |
| Data Plane RBAC | Blobデータを読み書きするための権限。管理画面を開ける権限とは別 |
| Private Endpoint / DNS | アプリからStorageへ、専用VNet内の経路で接続するための仕組み |
| ETag | 保存された内容の版を識別する値。古い画面で新しいファイルを誤削除しないために使う |
| SHA-256 | ファイルの中身が同じかを調べるチェックサム。暗号化やログインに使うものではない |

「コンテナー」は2か所に出てきますが、意味が違います。Container Appsのコンテナーはアプリを実行するもの、Blobコンテナーはファイルをまとめるものです。
また、`files/` はBlob名の先頭部分です。今回はHNSや、実際のフォルダーを持つファイルシステムは作りません。

CSVには行と列がありますが、Blobにはファイルとして保存します。表やグラフにするのはアプリの仕事です。
SQLへの登録、Redisへのキャッシュ、Power BIモデルの作成は、この回では行いません。

### Task 2 — 架空CSVをダウンロードする（5分）

アプリ内の **基本CSV（合計1020）** と **比較CSV（合計1080）** のリンクから、端末へ保存します。

ダウンロードしたものをそのまま使います。Excelなどで保存し直したり、文字コードを変換したりする必要はありません。

基本CSVの内容:

```csv
month,value
2026-01,100
2026-02,160
2026-03,120
2026-04,180
2026-05,220
2026-06,240
```

| 確認項目 | 基本CSV | 比較CSV |
| --- | --- | --- |

| 最大値 | **240** | **300** |
| 変えたところ | — | 6月の240を300へ変更 |

どちらも架空の月別データです。金額や個数を表すとは決めていないので、この実習では単に「値」と呼びます。

### Task 7 — 比較CSVを保存し、違いを見る（5分）

1. `monthly-sales-updated.csv`を選び、**Blobへアップロード**します。
2. 新しいファイルIDと、合計 **1080**・最大値 **300**を確認します。
3. 表の6月が **300**に変わり、最も長い棒も300になったことを確認します。
4. 一覧から最初の基本CSVのIDへ戻し、合計 **1020**・最大値 **240**のままであることを確認します。

このアプリは別ファイルとして保存するので、元のCSVは上書きされません。
同じ名前で再アップロードしても、別の空きIDに保存します。選ぶときは、名前とIDの両方を見てください。
業務で同じデータを再送する場合の重複検知や再実行の設計は、この動作とは別に考える必要があります。

### Task 8 — 不正なCSVが保存されないことを確認する（5分）

1. 講師が案内した[列名が違うCSV](app/blob_viz/samples/invalid-columns.csv)を使います。
   内容は`date,total`なので、指定の`month,value`ではありません。
2. アップロード前の保存済み件数を控えます。
3. そのCSVを選び、アップロードします。
4. **先頭行はmonth,valueの2列にしてください**というエラーを確認します。
5. 一覧を再読み込みし、件数が増えていないことを確認します。

エラーが出て、件数が増えていなければ、形式の違うCSVを保存前に止められています。
受け付けるのはUTF-8（BOM可）、64 KiB以内、1〜24行のCSVです。月は2000〜2099年の `YYYY-MM` で重複なし、値は0〜1000000の整数にします。
負数・小数・計算式・追加列は受け付けません。試すのは配布した不正入力のサンプルだけにし、本番データや巨大ファイルは使わないでください。

![列名の違うCSVを拒否した画面。問い合わせに使う要求IDは隠している](assets/app/05-invalid.png)

列名が違うためHTTP 400が返り、保存件数は増えませんでした。
画像の要求IDは隠しています。自分の画面では、講師への問い合わせに使うIDとして控えてください。

## Exercise 4: ファイルとリソースを片付ける

### Task 9 — 今回のファイルだけをアプリから削除する（5分）

1. 一覧で、**自分が今回保存したファイル名とID**を選びます。
2. **このファイルをBlobから削除**を選び、確認画面の対象を読みます。
3. 確認して削除し、一覧からそのIDが消えることを確認します。
4. 比較CSVも同様に、自分の対象だけを削除します。
5. ページを再読み込みし、今回のファイルが残っていないことを確認します。

削除時にはETagを使い、画面で見たものと同じ版かを調べています。
「保存されたファイルが変更されています」と出たら、一覧を更新して対象を見直してください。
消すのは自分が保存したファイルだけです。他の人のファイル、共有コンテナー、Storageアカウント全体を消す操作ではありません。
Soft Deleteや保持設定が有効な場合は、一覧から消えてもデータが保持されることがあり、課金条件も設定によって変わります。

![2ファイルを削除したあと、ページを開き直して保存済み0件になった画面](assets/app/06-deleted.png)

自分の2ファイルを削除し、開き直して0件になった画面です。この時点では、アプリやStorageなどのAzureリソースは残っています。

### Task 10 — 専用リソースの削除担当と完了を確認する（講師・主催者と実施）

ファイル削除だけでは、Container App・環境・Storage・ACR・Private Endpointなどは残ります。
この回では、講師が専用RGのリソースを削除します。参加者はファイルの削除結果と、途中で止まった箇所を伝えてください。

| 参加者 | 講師・主催者 |
| --- | --- |
| 自分の今回のファイルだけを削除 | 対象の契約・専用RG・所有マーカー・構成を確認 |

| リソースの削除担当と確認期限を控える | RG・アプリ・環境・Storage・ACR・PEが残っていないか確かめる |

サービス管理の`ME_...`のリソースを参加者が手動編集・削除しないでください。

環境の削除は20分以上かかることがあります。権限・ロックの問題や処理待ちがあれば未完了と記録し、主催者と削除担当・期限を決めて引き継ぎます。
請求データは遅れて反映されるので、0円表示ではなく、リソースが削除されたことを確認してください。

<details>
<summary>解答例</summary>

ブラウザーからの保存・読み込みはアプリAPIを通り、アプリがマネージドIDとBlobのデータ権限を使って実行します。
ページを開き直しても同じデータが出ることで、保存先にファイルが残っていて、読み直せることを確かめられます。
Azureリソースを管理する権限と、Blobの中身を読む権限は別です。さらに、この構成ではPrivate Endpointへの接続経路も必要です。鍵や全ネットワークの許可で置き換えません。

</details>

## 困ったとき

| 困っていること | 確認すること・対処方法 |
| --- | --- |
| アプリURLを開けない | 専用URL、HTTPS、許可されたネットワーク、講師のIP設定を見直します。全IPを許可する設定には変えません。 |
| ローカルテストの注意が出る | Azureに保存する画面ではありません。講師に実際の接続先を聞き、実習は未完了としておきます。 |
| 保存先へのアクセスを拒否された | アプリのID、Blob Data Contributorの範囲、権限の反映待ち、ネットワークを講師に調べてもらいます。 |
| Storageにつながらない | Private DNS、PEの承認、VNet統合を講師に調べてもらいます。公開Storageやキーには切り替えません。 |
| 保存できたが、グラフが出ない | 保存IDを控え、一覧を読み直してください。再アップロードを繰り返すと、別のファイルが増えてしまいます。 |
| 文字コード・列・月・値のエラー | 配布したUTF-8のCSVをそのまま使います。Shift-JISで保存し直したり、列名を変えたりしないでください。 |
| 64 KiBや10件の上限に達した | 配布した小さなCSVを使い、今回保存した不要なファイルだけを選んで削除します。 |
| 開き直したら違う値が出た | 同じファイルIDを選んでいるか、読み込みにエラーがないか、保存元、表と合計を見直します。 |
| 同じ画面からの操作を求められる | ページを再読み込みしてください。セッションが変わった場合の案内なので、CSRFの保護は解除しません。 |
| 古い版の削除を拒否された | 表示したあとで対象が変わっています。読み直して、ファイルと版を見直してください。 |
| PortalからBlob一覧を読めない | データ権限やPEへの経路がなければ読めません。この実習ではアプリから見ます。鍵・SAS・公開許可で回避しないでください。 |
| リソースを削除中／削除に失敗した | 未完了と記録し、今回の専用RGを削除する担当者と確認期限を、主催者と決めておきます。 |
