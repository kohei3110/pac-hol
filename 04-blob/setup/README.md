# 第4回の作成ファイル

この一式は、座学後の自習で、Microsoftから付与されたサブスクリプションに自分の環境を作るためのものです。
アプリのソース、Bicepの設定、段階ごとに実行するPythonスクリプトが入っています。
作成済みのAzure環境や、講師のイメージ・キーは入っていません。

使い方は第4回手順書のTask 1〜8を参照してください。

1. 自分の個人識別名で、空の`rg-hol04-識別名`をPortalから作る。
2. RGに`Purpose=AzureHandsOn`、`Session=04`、`Participant=識別名`のタグを入れる。
3. ZIPをCloud ShellのBashへアップロードし、展開する。
4. `init`にサブスクリプションID、識別名、**PCのブラウザーで確認したIPv4**を指定する。
5. `prepare`でStorage、ID、権限、ACR、VNet、PE/DNS、環境を作る。
6. Portalで、できたリソースと設定を確認する。
7. `build`で自分のACRへソースを送り、Linuxイメージをビルドする。
8. `deploy`でそのイメージのdigestを指定してContainer Appを作る。
9. アプリURLでCSVを保存・読み直し・比較・削除する。
10. 自分でRGを削除し、`check-cleanup`とPortalの一覧で削除完了を確かめる。

`init`は空の自分のRGにだけ実行します。それ以降は`.lab04-state.json`で対象、所有マーカー、デプロイ名、実ビルド番号、digestを確認します。
既存の処理を記録して、待ち時間に戻ったときは同じ処理を確認します。再実行で別のRGやビルドを増やしません。
ビルド受付後に番号だけ記録できなかった場合は、ACRのTasks→Runsで同じイメージタグの成功実行を探し、
`python3 setup_lab.py build --resume-run 実行番号`で記録へ戻せます。別タグの実行は受け付けません。

**一時Cloud Shellでは、閉じるとファイルが消えます。**
各段階の完了後、Manage files→Downloadから`.lab04-state.json`を手元に保存してください。
再開時はZIPを展開し直し、同じフォルダーにその記録をUploadします。
記録を失った場合は、Portalで作成済みのものを確認し、今回の自分のRGを削除してから新しく始めます。
空でないRGでinitをやり直して上書きすることはできません。
空でも前の作業タグが付いているRGは、記録を戻すか片付けてから始めます。

RBACロール割り当てには別の許可が必要です。Contributorだけで進められるとは限りません。
権限・ポリシー・クォータのエラーは、付与元へ必要な操作を伝えてください。
Storageの鍵やSAS、全IP許可で回避する手順はありません。

このスクリプトはRGの作成・削除を代わりに行いません。その二つは自分のPortalから操作します。
`check-cleanup`は記録したRGと、その環境の管理用RGが消えたかを見るだけで、削除コマンドは実行しません。
基盤作成を始めたあとで管理用RGの記録がない場合は、全体の削除完了とは判断せず、Portalでの確認を案内して止まります。
失敗・途中終了でも、作成済みのリソースを残さないようにしてください。
