## 運営の前提

第4回も、座学のあとに参加者が自分で進める自習です。
Microsoftから付与するのはAzureサブスクリプションです。講師は、アプリ、Storage、ID、ネットワーク、RGを事前に作りません。
作成からビルド・展開・データ操作・RG削除まで、本人が進めます。

アプリのソースと設定は教材として配布します。配布ファイルは、作成済みリソースや講師用イメージではありません。
参加者が自分のACRでビルドし、自分のContainer Appへ配置するので、プログラミングやPCへのDocker導入は求めません。

以前の45〜60分は用意済みアプリの操作だけの時間でした。今回の構築を含む自習は**120〜150分、さらに削除待ち30分程度**を見込んでください。
初学者の実測時間ではないので、配布前の試行で見直します。

## サブスクリプションの案内で伝えること

参加者に伝えるのは、付与アカウント・ディレクトリ・サブスクリプション、利用期限、費用の扱い、利用可能な地域、問い合わせ先です。
リソースは本人が作るため、事前作成済みのURLやStorageを配りません。

作成権限に加え、今回のBlobコンテナーとACRでRBACロールを割り当てる許可が必要です。
**Contributorだけでは通常できません。** 権限不足のまま教材を配り、「キーを使えばよい」と回避させることはしません。
付与環境の支援担当へ、必要な操作と対象の範囲を確認してください。

`Microsoft.App`、`Microsoft.Network`、`Microsoft.Storage`、`Microsoft.ManagedIdentity`、`Microsoft.ContainerRegistry`、`Microsoft.CloudShell`の登録、
Japan Eastのクォータや組織のポリシーも、付与環境で利用できる必要があります。
それは利用条件の確認で、講師がアプリ基盤を用意することとは別です。

## 作成を段階に分けた理由

保存先、権限、ネットワーク、イメージを全部一度に操作すると、どこで止まったのか分かりにくくなります。
配布スクリプトは次の段階に分けています。

| 手順 | 本人が行うこと | 確認すること |
| --- | --- | --- |
| PortalのRG作成 | 個人識別名の空のRGに実習タグを付ける | 名前、付与サブスクリプション、Participantタグ |
| `init` | 作成先、識別名、PCのIPv4を記録する | 自分の空のRGだけが対象 |
| `prepare` | Storage、ID/RBAC、ACR、VNet/PE/DNS、環境を作る | ARM validateと、今回のRG内だけのwhat-if |
| Portalの一覧 | 自分のリソースと設定を見る | Storageの非公開、PE承認、ID・権限の範囲 |
| `build` | 配布ソースを自分のACRでビルドする | 同じrunIdを追い、実イメージのdigestを記録 |
| `deploy` | Container Appを自分で展開する | MIでのイメージ取得、IP限定HTTPS、Blobアクセス |
| アプリの操作 | 保存、読取、比較、不正入力、ファイル削除 | 6行・1020・240、比較1080・300 |
| PortalのRG削除 | 本人が今回のRGを削除する | リソースの消失、管理用RGの片付け |

名前の例は`ksaito73`です。識別名は[共通ルール](../self-study.md)で本人が決めます。
StorageとACRにも識別名を含め、グローバルな重複を避ける文字列を足します。
固定名のDNSゾーンやサブネットは、自分のRGとVNetの中に作ります。

## 安全設定とデータの扱い

StorageはShared Key・匿名・公開ネットワーク無効です。
アプリのUser-assigned MIに、**uploadsコンテナーだけ**のStorage Blob Data Contributorと、**自分のACRだけ**のAcrPullを付けます。
PCからStorageへ直接つなぐCORSやSASは不要です。

アプリの入口はPCのIPv4一つに絞ります。
Cloud Shellの送信IPと、アプリを開くPCのIPは違う場合があるので、PCのブラウザーで確認する説明を入れています。
IP制限は利用者ログインとは違います。学習用の限定公開であり、本番の認証・データ分離の代わりにはなりません。

VNetはworkload profiles型Container Apps環境へ統合します。Consumptionだけを使い、
infrastructureサブネットは/27、PE区画は/24、委任先はMicrosoft.App/environmentsです。
SDKは通常のBlob URLを使い、Private DNSがPEのIPを返します。

CSVの上限は64 KiB、1〜24行、整数の値、重複しない月、固定10件です。
上書きしない条件付き保存、別GETでのBlob読取、SHA・ETagの検査、条件付き削除はアプリ側で行います。
テスト用のメモリー保存へ、本番で自動切り替えすることはありません。

## 再開と質問対応

Cloud Shellはストレージを追加しない一時セッションを使います。各段階で`.lab04-state.json`を本人のPCへ保存してもらいます。
この記録には実名ではない識別名、リソース名、ID、IP、実行番号が入ります。提出物として回収せず、本人が保管します。

セッションを閉じた場合はZIPを展開し直し、その記録を同じフォルダーへ戻します。
記録がないまま既存RGへinitを再実行することはできません。
失った場合は重複構築せず、本人が今回のRGを削除してから新しく始める形にします。

デプロイやビルドは、既存の処理を記録して続きを確認します。待ち時間が長いときに別の環境を作らせないことが大切です。
エラーには段階・対象名・安全なコードがあれば十分です。キー、トークン、全ログは受け取らないでください。

削除は本人がPortalから行います。失敗やロックのときだけ付与元へ相談し、解消後に本人が再開します。
`ME_...`の管理用RGはサービスに任せ、環境削除に伴う消失を確認します。直接削除させません。
