# 講師用 — プログラムから音声を送って確認する

参加者は[Foundryの画面](../guide.md)で進めます。
このフォルダーは、講師が音声の往復をプログラムから確認するときの補助ファイルです。

`requirements.txt`には、Azure AI Projects 2.8.0とEntra認証用の依存をまとめています。
`voice_checks.py`は、入力ファイルが24 kHz・PCM16・モノラルのWAVで、30秒以内かを確認します。
また、返答が最後まで返り、入力と出力の文字、無音ではない音声、発話開始・終了のイベントがそろっているかを調べます。
このファイルだけを実行しても、Azureにリソースは作られず、音声の送信や削除も行われません。

## 確認の進め方

Microsoftから付与された検証用サブスクリプションで、自分のRG・Foundryリソース・プロジェクトを新しく作ります。
参加者向けの準備済み環境を残すための検証ではありません。自分の個人識別名とタグで対象を確認し、最後に自分で削除します。
作成・接続・読取・削除の書き方は、[公式Python Quickstart](https://learn.microsoft.com/azure/foundry/agents/quickstarts/prompt-voice-agent?pivots=python)を参照してください。

今回の確認では、文字を入力して声を出すのではなく、合成した日本語音声そのものを送っています。
文字だけの会話だと、音声を受け付けられるか、話した内容を認識できるかが分からないためです。

1. 今回用の名前を決め、同名のエージェントがないことを確認します。
2. 同梱の初回用指示でVoiceエージェントを作ります。モデルはManaged、声は日本語のAzure standardを使います。
3. 入力はAzure Speechと日本語のAzure semantic VAD、最大出力は512トークン、会話保存は`store=false`にします。
4. 練習用音声を100msずつ送り、発話開始・終了、文字起こし、返答の音声、`response.done`の`completed`を確認します。
5. 接続にはタイムアウトを設定します。文字だけ返った、音声が途中で切れた、といった場合も記録してください。
6. 指示を変えてSaveした版に、同じ質問を送り、話し始めが変わるかを確認します。古い版も残っているか見ます。
7. 保存した内容を調べる場合だけ、その接続で`store=true`を指定します。音声も保存されるので、練習用の会話に限って使ってください。
8. `session.created`で返った会話IDを控え、日時・版・文字で今回の会話を照合します。
9. 接続を終了し、失敗した分も含めて今回の会話を削除します。エージェント、専用RGも順に片付けます。

削除後は、会話・音声の情報・エージェントが404になり、専用RGが一覧から消えたことを確認します。
Foundryリソースのsoft deleteは別に確認してください。
公開する記録には、段階と必要な結果だけを残し、トークンや全ログは載せません。

マイクの許可、人の声、ヘッドセットの音、発音、間、割り込みは、別に実機で試す必要があります。
プログラムで音声が返ってきても、会場で聞き取りやすいかまでは分かりません。
