# 第5回 — Foundryで音声AIエージェントを作る

Microsoft Foundryで音声AIエージェントを作り、日本語で会話します。
声や答え方を設定し、指示を変える前後で同じ質問への返答を聞き比べます。プログラムを書く必要はありません。

**第5回の座学後に取り組む自習用の手順書です。** Microsoftから付与されたAzureサブスクリプションを使ってください。
RG、Foundryリソース、プロジェクト、音声エージェントを作成し、終了時には削除します。
講師による環境の事前準備はありません。前の回のVMやアプリも不要です。

対象: AzureやAIを初めて操作する人  
目安: **90〜120分＋予備15分**。初回のリソース作成・権限反映の待ち時間を含みます  
操作: Azure PortalとFoundry。コード・Docker・APIキーの準備は不要です。必要な権限が画面で確認できない場合だけCloud Shellを使います  
更新日: 2026-10-13 ／ [共通の始め方と名前](../self-study.md) ／ [実施記録](run-through.md)

**教材の確認状況（制作版）:** プログラムから音声を送信する方法で、作成・会話・指示変更・削除を確認済みです。
Foundryの画面で最初から最後まで操作する確認と、マイク・ヘッドセットを使った会話の確認は未完了です。
配布前に、講師が実際に使う環境で確認してください。

> **この実習には料金がかかります。** 付与サブスクリプションの費用と利用期限を、Microsoftからの案内で確認しておきましょう。
> 会話には、この資料の練習用の質問を使ってください。業務情報や個人情報、パスワードは話さないでください。
> 音声はAzureに送られます。録音保存をオフにしても、端末の中だけで処理されるわけではありません。

## 始める前の準備と費用

次の項目を確認してから始めてください。

- [ ] Microsoftから付与されたサブスクリプションにサインインできる。
- [ ] RG、Foundryリソース、プロジェクトを自分で作成・削除できる。
- [ ] 自分のプロジェクトでFoundry User相当の権限を使える。必要な場合は、そのプロジェクトだけに自分で割り当てられる。
- [ ] 個人識別名、費用の扱い、利用期限、問い合わせ先を控えた。
- [ ] マイク付きヘッドセットを用意した。
- [ ] 音声をAzureに送ることと、録音の扱いを確認した。
- [ ] 周りの人の会話を拾わない場所で試せる。

作成権限とデータの操作権限は別です。**Contributorだけでは通常、RBACのロール割り当てはできません。**
権限が足りない場合は、対象のプロジェクト名と必要な操作を付与元に伝えてください。業務用のプロジェクトや講師の環境で代用しないでください。
`Microsoft.CognitiveServices`が未登録なら、サブスクリプションのリソースプロバイダーから、許可の範囲で登録します。

音声エージェントはプレビュー機能です。リージョンや利用する契約によって、選べるモデルや声が違います。
作成画面に**Voice**が表示されない場合は、講師に確認してください。従来のSpeech playgroundにあるVoice Liveのデモは、この手順とは異なります。

料金は、モデル、音声・文字の量、接続時間、録音の有無などによって変わります。Foundryが管理するモデルにも利用料金がかかります。
1回の会話は**約60秒、長くても2分**、会話の合計時間は**10分以内**を目安にしてください。
時間になっても自動で終了するわけではありません。使い終わったら、必ず画面の**End**で会話を終了します。

### 二つのポータルを使い分ける

| 開くサイト | この実習での使い方 |
| --- | --- |
| [Azure Portal](https://portal.azure.com/) | 自分のRG、Foundryリソース、プロジェクトを作り、権限を確認する。最後のRG削除にも使う |
| [Microsoft Foundry](https://ai.azure.com/) | 自分のエージェントを作り、声や指示を設定し、会話を試す |

リソースの作成にはAzure Portal、エージェントの設定と会話にはFoundryを使います。両方で同じアカウント・ディレクトリを選んでください。

## 今日作るものと覚える言葉

![ブラウザーからFoundryの音声エージェントにつながる流れ。Microsoft公式アイコンを使用](assets/voice-flow.png)

マイクから入力した音声をFoundryが処理し、AIの返答を音声で返します。
音声を中継するアプリやContainer Appsは作りません。図は通信の流れを示したもので、操作画面ではありません。

操作画面に出てくる主な用語を、次の表にまとめています。

| 画面に出る言葉 | 意味 |
| --- | --- |
| RG | 今回のAzureリソースをまとめる場所。自分で作って最後に削除する |
| Foundryリソース | モデルや音声機能を利用するAzureの管理単位 |
| プロジェクト | 今回のエージェントを置く場所。自分のFoundryリソースの中に作る |
| Instructions | AIへの指示。「何をするか」「どんな話し方で答えるか」を書く |
| AI model | 質問を理解して、返答を考えるモデル |
| Managed | Foundry側で用意されたモデルを使う方式。自分でモデルをデプロイしなくてよい |
| Voice | 返答に使う声。話の内容を考えるモデルとは別に選ぶ |
| 文字起こし | 話した内容を画面に文字で表示すること |
| ターン検出（VAD） | 話し始めと、話し終わりを判断する仕組み |
| セッション | StartからEndまでの、一回の会話 |
| バージョン | 保存した指示や設定の版。Saveするたびに新しい版ができる |
| 会話保存（`store`） | 文字起こしと音声を残す設定。今回はオフで使う |

### 自分だと分かる名前を控える

`ksaito73`は個人識別名の例です。全回で使う自分の識別名に置き換えてください。
英小文字で始まる3〜10文字の英小文字・数字にします。フルネームやメールアドレスは名前に使いません。

| 作るもの | 名前の例 |
| --- | --- |
| RG | `rg-hol05-ksaito73` |
| Foundryリソース | `f-hol05-ksaito73-7q2m9c` |
| 最初のプロジェクト | `proj-hol05-ksaito73` |
| Voiceエージェント | `voice-hol05-ksaito73` |

Foundryリソース名の末尾は、重複を避けるために自分で選んだ6文字程度の英小文字・数字です。例の`7q2m9c`も変えてください。
同じ名前が使われている場合は、末尾の文字列を変えて控え直してください。既存リソースは使いません。

## Exercise 1: RGとFoundryを作る

### Task 1 — 自分のRGを作る（5〜10分）

1. [Azure Portal](https://portal.azure.com/)へサインインし、Microsoftから付与されたサブスクリプションを確認します。
2. **リソースグループ→作成**を開き、RG名を`rg-hol05-自分の識別名`にします。
3. 利用が許可された**Japan East**を選びます。Voiceとモデルの提供状況は地域・契約で違うので、付与元の案内も確認します。
4. **タグ**に`Purpose=AzureHandsOn`、`Session=05`、`Participant=自分の識別名`を入れます。
5. **確認および作成→作成**をクリックし、空の自分のRGができたことを見ます。

### Task 2 — Foundryリソースと最初のプロジェクトを作る（10〜20分）

1. [Foundryリソースの作成](https://portal.azure.com/#create/Microsoft.CognitiveServicesAIFoundry)を開きます。
2. 付与サブスクリプションと**Task 1で作った自分のRG**を選びます。
3. Foundryリソース名に、控えた`f-hol05-自分の識別名-ランダム文字列`を入れます。
4. リージョンは今回の許可地域、プランが表示される場合は**S0**を選びます。
5. **Default project name／最初のプロジェクト名**を`proj-hol05-自分の識別名`にします。
6. 自分のリソースと最初のプロジェクトのマネージドIDが作られる設定を使います。既存の仕事用Storageやネットワークには接続しません。
7. **Inbound Networking／受信ネットワーク**は、付与環境で許可された方法を使います。公開ネットワークを使える環境では、**選択したネットワークとIP**だけに絞り、現在のPCのIPv4を追加します。
   画面で設定できなければ、作成直後に自分のリソースのネットワークで設定します。接続できないからと全IPへ広げません。
8. **タグ**に自分の実習タグを付け、内容と料金を確認して**作成**をクリックします。
9. デプロイ完了後、**リソースに移動**を開き、自分の名前のリソースとプロジェクトができたことを確認します。

![Foundryリソースと最初のプロジェクトを用意する、実Azure Portalの作成前の画面](assets/portal/01-foundry-create.png)

画像は作成前の設定画面です。サブスクリプションと名前は、本文に従って入力してください。画像の既定リージョンは実習で使う地域とは異なります。

![①RG、②Foundryリソース名、③リージョンの入力欄を拡大した画面](assets/portal/02-foundry-basics-detail.png)

①は今作った自分のRG、②はFoundryリソース名、③は利用してよいリージョンです。

![最初のプロジェクト名の欄を①で示した拡大画像](assets/portal/03-default-project-detail.png)

①の`proj-default`は既定値なので、自分の`proj-hol05-...`へ変えます。エージェントの名前は、あとで別に付けます。

### Task 3 — Entra認証と、自分のプロジェクトの権限を確認する（5〜15分）

Voiceの操作には、リソースの作成権限とは別にデータの操作権限が必要です。
Portalでの作成時にロールが自動で割り当てられる場合もあります。次の手順で確認してください。

1. 自分のFoundryリソースの**ID／Identity**で、システム割り当てIDが有効であることを確認します。オフなら、その自分のリソースで**オン→保存**を選びます。
2. **ネットワーク**で、許可したPCのIPまたは付与環境の指定経路になっていることを確認します。
3. キーによるローカル認証は使いません。無効化がまだなら、Cloud Shellの**Bash**で次の自分のリソースだけに設定します。三つの説明部分を自分の値へ置き換えます。

```bash
az resource update \
  --subscription "自分のサブスクリプションID" \
  --resource-group "rg-hol05-自分の識別名" \
  --name "自分のFoundryリソース名" \
  --resource-type "Microsoft.CognitiveServices/accounts" \
  --set properties.disableLocalAuth=true
```

4. Foundryで自分のプロジェクトを開き、**Manage→Project details**から自分のアクセスを確認します。
   Azure Portalへのリソースリンクがある場合は、その**プロジェクト**の**アクセス制御（IAM）→アクセスの確認**でも確認できます。
5. **Foundry User**または同等の権限がすでにあるなら、新しく付ける必要はありません。
6. ない場合は、自分のプロジェクトの**ロールの割り当ての追加**でFoundry Userを選び、ユーザー・グループのメンバーに**自分だけ**を指定します。
   **対象はそのプロジェクトだけ**です。サブスクリプション全体や他人のプロジェクトには割り当てません。
7. 完了後に画面を更新し、反映を待ちます。追加できない場合は、付与元へ必要な権限を確認します。

画面にプロジェクトのリンクがない場合は、[自分のプロジェクトの権限を確認するコマンド](permissions.md)でも対応できます。
HTML版ではリンク先に、PDF版では巻末に載せています。
Cloud Shellには自分のEntraアカウントでサインインしてください。キーやトークンのコピーは不要です。

### Task 4 — 自分で作ったプロジェクトのAgentsを開く（5分）

1. [Microsoft Foundry](https://ai.azure.com/)を同じアカウントで開き、新しいFoundry画面を使います。
2. プロジェクトの選択で、今作った`proj-hol05-自分の識別名`を選びます。
3. 必要に応じて**Build→Agents**を開きます。
4. Voiceプレビューが利用できることを確認します。利用できなければ、Textで代用せず付与元に確認してください。

Agentsにエージェントの一覧が表示されます。作成前に、開いているプロジェクト名をもう一度確認してください。

## Exercise 2: 音声を設定して話す

### Task 5 — Voiceを選んで作成する（5分）

1. **Build an agent**をクリックします。
2. **Create an agent**の画面で、**Agent name**に`voice-hol05-自分の識別名`を入力します。例は`voice-hol05-ksaito73`です。
3. **Interaction mode**で**Voice**を選びます。Textは、文字を入力して会話するエージェントです。
4. 用途を選ぶ欄があれば、一般的な案内や学習支援に近いものを選びます。
5. **Create agent and open playground**をクリックします。

作成が完了すると、設定と会話テストを行うPlaygroundが開きます。
名前に関するエラーが出た場合は、画面に表示された命名条件に従って修正してください。

**VoiceとTextは、作成後には切り替えられません。** Textで作ってしまった場合は、講師に相談してVoiceで作り直します。

### Task 6 — AIに答え方を教える（5分）

左側の設定欄にある**Instructions**を開きます。
AIの役割や答え方を指定する欄です。次の文章をそのまま貼り付けてください。

```text
あなたはAzure初学者向けの学習用音声AIです。
日本語で「こんにちは。」に続けて短い一文だけ答え、合計70文字以内にします。質問は一度に一つだけにします。
VMの停止の質問には「停止してもディスク料金は残るので、専用リソースの削除確認が必要です。」と説明します。
Azure操作の依頼には「削除は実行できませんので、講師と対象を確認してください。」と答えます。
あなたには操作ツールがありません。作成や削除が成功したとは言いません。
業務情報、個人情報、パスワード、鍵は求めません。不明なことは講師への確認を案内します。
```

貼り付けたら**Save**をクリックし、画面に表示された版を控えます。
[指示のテキストファイル](assets/instructions-v1.txt)からコピーしても構いません。

後で指示の変更を確認しやすいよう、返答を「こんにちは。」から始める指定を入れています。
同じ指示でも、AIの返答は毎回少しずつ変わります。一字一句の一致だけでなく、指定した内容を説明しているかも確認してください。

### Task 7 — モデルと日本語の声を選ぶ（5分）

設定欄の**AI model**と**Voice**を開き、次の内容を確認します。

| 項目 | 今回使う設定 |
| --- | --- |
| モデルの管理方式 | **Managed**。自分でモデルを用意するSelf-deployedではない |
| AI model | `gpt-realtime-2.1-mini`。表示されない場合は講師の指定を使う |
| Voice | 日本語のAzure standardの声。確認済みの例は`ja-JP-NanamiNeural` |
| 返答の言語 | 日本語。先ほどのInstructionsにも書いてある |
| Tools・Knowledge bases | 今回は追加しない |
| Avatar・電話・Publish | 今回は使わない |

**AI modelは「何と答えるか」、Voiceは「どんな声で話すか」の設定**です。
試聴機能がある場合は、日本語の声を確認してください。

選べる声はモデルによって違います。上の声が出ない場合は、設定を無理に合わせず講師に聞いてください。
モデル欄の応答時間の表示（ms）は目安です。実際の会話の応答時間を保証するものではありません。

### Task 8 — 聞き方と録音の設定を確認する（5分）

1. **Advanced settings**を開きます。
2. 文字起こしを選べる場合は**Azure Speech**を選び、入力言語を「Japanese／日本語（日本）」にします。
3. **Automatic turn detection**で**Azure semantic**を選びます。
4. **Interrupt response**があれば、オンのままにします。AIが話している途中でも、こちらから話しかけられる設定です。
5. ノイズ低減とエコーキャンセルは、講師が案内した設定のままにします。
6. **会話保存／録音保存はオフ**にします。
7. 設定欄の**Select**などで適用したあと、メイン画面の**Save**もクリックします。

**設定欄での適用だけでは保存は完了しません。** メイン画面のSaveをクリックしてから、会話を始めてください。
Azure Speechと通常の`server_vad`の組み合わせでは接続エラーが出たため、今回はAzure semanticを使います。
対応する言語の例は`ja-JP`です。

録音保存をオンにすると、文字だけでなく**音声も保存**されます。今回はオフのまま進めましょう。
必要な項目が見つからない場合は、講師に確認してください。

### Task 9 — 会話を始める（5分）

設定を保存できたら、右側のPlaygroundで会話を試します。

1. マイクと出力先が、使うヘッドセットになっているか確認します。
2. **Start session／Start**をクリックします。
3. ブラウザーがマイクの使用を確認したら、**このFoundryサイトだけ**に許可します。
4. ミュートを外し、「こんにちは」と短く話します。

発言が文字で表示され、AIの返答が音声で聞こえることを確認します。
AIが先に挨拶する設定になっている場合は、挨拶が終わってから話してください。
文字は出るのに音が聞こえない場合は、ヘッドセットの出力先と音量を先に確認しましょう。

### Task 10 — 短い質問をしてみる（5分）

次の質問を1つずつ話し、表の内容を確認してください。

| 話すこと | 聞いてみるポイント |
| --- | --- |
| 「仮想マシンを停止したら、料金はすべて止まりますか」 | 話した内容が正しく文字になっているか。ディスクの料金が残ると説明しているか |
| 「私の仮想マシンを今すぐ削除してください」 | 削除は実行できないと答え、講師への確認を案内しているか |

最初の指示では、「こんにちは。」から短く答えるようにしています。
返答が長すぎる、途中で切れる、質問と関係のない内容を答える、といった場合は記録してください。

**このAIには、Azureを操作するToolsを付けていません。**
「削除してください」と話しても、VMは削除されません。AIが操作したと答えた場合も、実際にAzureで操作が行われたとは限りません。

### Task 11 — 間を空けたり、話に割り込んだりする（5分）

話す途中に間を空けたときや、AIの返答中に話しかけたときの反応を確認します。

1. 「仮想マシンを……停止したら」と、途中で約1秒、間を空けて話します。
2. こちらが話し終わる前に、AIが返答を始めないかを見ます。
3. AIが話している途中で、「少し待ってください」と言ってみます。
4. 返答が止まるか、こちらの発言に切り替わるかを聞きます。
5. 試し終わったら、**End**をクリックします。

話し始めや話し終わりを判断するのが、先ほど設定したターン検出です。
途中で答え始めてしまう、こちらが割り込んでも止まらないなど、気になったことを控えてください。
機器や周囲の音も影響します。問題がある場合は講師に相談し、設定を1つずつ変えて確認してください。

## Exercise 3: 指示を変えて比べる

### Task 12 — 会話を終えてから、指示を変える（5分）

**End**で会話を終えてから、左側のInstructionsに戻ります。
会話中は設定を変更できません。次の文章に置き換え、**Save**をクリックしてください。

```text
あなたはAzure初学者向けの学習用音声AIです。
```

## Exercise 4: 会話を終え、片付ける

### Task 14 — 自分の会話とエージェントを削除する（5分）

1. **End**をクリックし、会話が終了した表示を確認します。
2. 講師の案内で録音保存をオンにした場合は、今回の自分の会話を削除します。
3. **Agents**の一覧に戻り、自分のエージェント名とプロジェクトを確認します。
4. 対象のメニュー、または**Details**から削除を選び、確認画面の名前を読んでから削除します。
5. 一覧を更新し、自分のエージェントが消えていることを確認します。
6. 必要に応じて、ブラウザーのFoundryサイトのマイク許可を解除します。

**削除は取り消せません。** 他の人の会話や、仕事用のエージェントを選ばないようにしてください。
録音の削除ボタンがない場合は、その会話を管理するAPIかプロジェクトの削除方法を確認します。今回は録音を残さず、最後に自分のプロジェクトごと削除します。
削除権限がない場合は付与元へ相談し、解消後に自分で再開してください。

会話を削除すると、その文字起こしや返答、音声も一緒に削除されます。
録音保存をあとからオフにしても、すでに保存された会話は残るので、削除が必要です。
削除できなかったものは、そのまま講師に引き継ぎましょう。

### Task 15 — 自分のFoundryリソースとRGを削除する（5〜20分）

会話とエージェントを削除しても、**Foundryリソースとプロジェクトは残っています。**
Endによる会話の終了だけでも、これらのリソースは削除されません。Azure PortalでRGを削除します。

1. Azure Portalへ戻り、`rg-hol05-自分の識別名`を開きます。
2. 付与されたサブスクリプション、RG名、Participantタグが自分の控えと合うことを確認します。
3. 今回のFoundryリソースとプロジェクトだけが対象であることを見ます。誤ってモデルデプロイを追加した場合は、それも自分の対象だけを先に削除します。
4. **リソースグループの削除**をクリックし、自分のRG名を入力して削除します。
5. 通知で処理状況を確認します。リソース作成が途中で失敗した場合も、今回のRGは片付けます。

共有RG、仕事用のRG、他の人のリソースは選びません。

### Task 16 — RGとFoundryリソースが消えたことを確認する（5分）

1. **リソースグループ**一覧を更新して、自分のRG名を検索します。
2. **RGが表示されない**ことを確認します。
3. **Foundryリソース**一覧を更新し、自分の名前で検索します。**Foundryリソースが表示されない**ことを確認します。
4. Foundryのプロジェクト選択も更新して、自分の今回のプロジェクトが残っていないことを見ます。
5. 削除エラーがあれば「未完了」と記録し、付与元へ対象と理由を伝えます。原因が解消したら自分で削除を再開します。

Foundryリソースは、削除後も48時間は回復できる状態で残る場合があります。この仕組みがsoft deleteです。
同じ名前ですぐ作り直したいときは、恒久削除の**Purge**が必要になりますが、元に戻せません。
今回は自分のリソース削除までを確認し、Purgeは通常の自習には含めません。必要なときは、対象を照合して付与元の許可・案内に従います。

自分でモデルをデプロイした環境では、そのモデルの料金と削除も確認が必要です。今回はManaged方式なので、モデルのデプロイは作りません。

## 困ったとき

| 困ったこと | まず試すこと |
| --- | --- |
| Voiceが出ない | 新しいFoundry画面と、案内されたプロジェクトを使っているか確認し、講師に相談する |
| モデルや日本語の声が見つからない | 別の設定で進めず、開催環境で使える組み合わせを講師に聞く |
| 作成できたのに、会話が始まらない | Saveできているか確認する。Azure SpeechとAzure semanticの組み合わせも講師と見る |
| マイクを使えない | Foundryサイトの許可、ヘッドセットの入力先、OSのマイク設定を確認する |
| 文字は出るが、音が聞こえない | 出力先、音量、ミュートを確認する |
| 日本語が違う言葉になる | 入力言語とマイクを確認し、短い質問を一つずつ話す |
| 返答が長い、途中で切れる | Instructionsを確認する。講師に、どの質問で止まったかを伝える |
| 指示の変更が反映されない | End→指示変更→Save→新しいStartの順に確認する |
| 話の間や割り込みが不自然 | 周りの音や機器、ターン検出を講師と確認し、一つずつ調整する |
| 過去の会話やログが見つからない | 会話保存の設定を講師に確認する。会話保存とApplication Insightsのトレースは別の仕組み |
| 削除できない、処理が終わらない | 未完了の内容を、対象名と一緒に削除担当へ伝える |
