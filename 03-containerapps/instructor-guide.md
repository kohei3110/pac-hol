**第3回の座学後の自習です。** Microsoftから付与されたAzureサブスクリプションで、参加者がRG、環境、アプリを作成し、自分で削除します。

## 開催前に用意しておくこと

1. 使うサブスクリプション、RGの作成・更新・削除権限、費用の負担者、提出先、質問窓口を決めておきます。
2. Microsoft.Appの登録、リージョン、Consumptionのクォータ、環境数の上限を調べ、人数分の余裕を確保します。
3. MCRで `fb699ef` と `c6f1515` の両方を取得できるか試します。取れない場合も、latestに変えてそのまま開催することは避けてください。
4. 参加者のブラウザーからPortalと外部HTTPSのサンプルを開けるか、組織の公開・外向き通信のルールも確認します。
5. サンプルは環境変数を表示するので、秘密値・業務データ・マネージドID・接続情報は追加しません。実習用として短時間だけ使い、本番コードには流用しないでください。
6. 各リビジョンが0.25 vCPU／0.5 GiB、最小0・最大1になっているか見ます。2版なら、同時に2レプリカ動くことがあります。
7. ログ保存、Dedicated、ACR、VNet、DB、Jobsは追加しません。組織で必須の設定がある場合は、主催者が料金と手順を調整します。
8. 開催用のPortalで、旧版固定 → 新版preview → 新版100% → 旧版100% → 削除を一度通して試します。CLIで確認した結果とは分けて記録してください。
9. 初学者に手順書だけで試してもらい、URLの取り違え、キャッシュ、スケールゼロからの起動待ちで迷わないか見ます。
10. 終了後にRG・アプリ・環境の削除を確認する担当者と、削除できなかった人から引き継ぐ担当者・期限を決めます。

## 自習で見込む時間

| 経過 | 内容 | チェックポイント |
| --- | --- | --- |
| 0〜10分 | 付与環境・個人識別名・自分のRG作成 | RG名とParticipantタグ、秘密なしの一時サンプル |
| 5〜20分 | 環境と旧版の作成 | Consumption、port80、外部HTTPS、小型 |
| 20〜30分 | 応答確認・Multipleと旧版固定 | 共通URLの旧版、具体名100%、Latestなし |
| 30〜40分 | 新版の作成 | イメージ＋環境変数更新。旧版100%を保持 |
| 40〜48分 | previewの確認 | 共通URLは旧版、別URLは新版 |
| 48〜58分 | 新版100%と旧版100% | 同じURLの応答が旧→新→旧 |
| 58〜65分 | 変更範囲・費用の振り返り | 100%とActive、ラベルと共通URLの違い |
| 65〜75分 | 削除と残存確認 | RG・アプリ・環境が消えた |

予備時間を15分取っておきます。待ち時間が長ければ、振り返りを短くして削除を優先してください。
検証では環境の削除に20分以上かかったので、自習を終える前に本人が一覧で確認します。処理中なら未完了とし、通知と残存を追跡します。
権限やロックで進まなければ付与元へ相談します。通常のRG削除を講師へ任せる手順ではありません。
Job、イメージビルド、APIM、認証、カナリア50/50は別の発展課題です。この回の作成・切り替え・切り戻し・削除を終えてから扱ってください。

## 迷いやすい点

**Latestではなく、旧版の名前を選びます。**
Multipleにして、旧版の具体名を100%に固定してから新版を作ります。初回名は自動生成でもよく、資料で呼ぶ「旧版」と `v1` という名前は同じ意味ではありません。

**共通URLとpreview URLを並べて見ます。**
割合が適用されるのは共通URLで、previewラベルURLは指定した版に直接つながります。新版が0%でも開けるので、両方のURLと返った版を控えてもらってください。

**新版が動いてから切り替えます。**
準備完了・Activeになり、previewで応答を見られたら切り替えます。イメージ取得や起動に失敗した場合は、旧版100%のまま調べます。既存リビジョンを消したり、表示する値だけ変えたりはしません。

**切り戻しても、データまでは戻りません。**
残した旧版へ送り先を戻す操作で、旧イメージをv3として作り直す操作ではありません。外部DBを使う本番アプリでは、スキーマやデータの互換性も必要です。この実習ではDBを使っていない点を添えてください。

## 再開・途中終了

| 状態 | 再開点 |
| --- | --- |
| 未作成 | Task 1から始めます。 |
| 環境だけ作成済み | 自分の専用環境を選び、Task 3から再開します。環境を追加で作る必要はありません。 |
| 旧版が応答する | Task 5から再開します。 |
| 新版が作成済み | 新版の設定・準備状態と旧版100%を見直し、Task 7から再開します。 |
| 新版に切り替え済み | Task 9の切り戻しに進みます。 |
| 切り戻し済み | Task 11の削除に進みます。 |
| 削除中／失敗 | 通知と一覧を見ます。終わっていなければ、担当者に引き継ぎます。 |

終了時には個人識別名、どこまでできたか、旧→新→旧の確認結果、迷ったTask、自分のRGの削除結果を記録します。
`rg-hol03-ksaito73`、`cae-hol03-ksaito73`、`ca-hol03-ksaito73`のように、本人が選んだ識別名で揃えます。
全環境変数、実際のURL、トークン、加工前の画面は回収しません。

## 再現に使ったファイル

初回の旧版を作るテンプレートは `infra/handson03-validation.bicep` と `infra/handson03-application.bicep` です。参加者は実行しません。
RG名・環境名・アプリ名・所有マーカーを指定し、既存RGを再利用しない検証コードから使います。
ARM検証とwhat-ifで新規3リソースだけが対象になることを見てから、CLIで新版と割合を操作し、各段階の実際の応答を調べます。
更新後にこのテンプレートを繰り返し適用して切り戻す手順ではありません。結果は[実施記録](run-through.md)にまとめています。
