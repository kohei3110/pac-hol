## 開催前に用意しておくこと

1. 使うサブスクリプション、誰が費用を負担するか、終了時刻、提出先、質問窓口を決めておきます。
2. 参加者がRGを作れるか、指定のVMサイズを使えるか確認します。リージョン全体とDaldsv6ファミリーのvCPUクォータに、VM1台あたり2 vCPU×同時参加人数分の余裕があるか確認します。サービスによってはファミリー名がDaldv6と表示されます。BastionとStandardの公開IPv4の利用制限も確認してください。
3. Microsoft.Compute／Microsoft.Networkの登録と、組織のリージョン・SKU・タグ・ネットワークのポリシーを確認します。
4. 参加者が専用RG内でVM・NSG規則・VNet・Bastion・公開IPを作成でき、**専用RGを削除できる**ことを確認します。
   この回は本人がRGも作るので、サブスクリプション側のRG作成権限が必要です。
5. 接続には、VM・VMのNIC・Bastionに対するReader相当の閲覧権限と、VM内の認証が必要です。
   今回はSSH鍵でログインするため、Entra IDログイン用の拡張機能やVM Loginロールは追加しません。
6. 参加者のPCでRSA鍵をダウンロードし、接続時にファイルを選択できるか確認します。PortalとBastionのHTTPS・WebSocket通信も確認してください。
7. Ubuntu 24.04 x64 Gen2、Standard_D2alds_v6（2 vCPU・4 GiB）、Trusted launch、Standard HDD LRS、高速ネットワーク有効を利用できるか確認します。
8. 費用を見積もります。Basicの公開価格の例は$0.19/時ですが、契約・通貨・課金単位による違いと、ディスク・IP・転送・ポリシーで有効になる有料サービスの費用も確認してください。
   参加者数と、デプロイ・削除の待ち時間も含めて計算します。共有Bastionは使わず、本人が自分のものを片付ける構成にします。
9. 開催用のPortalで、BasicとRSA鍵を使って、作成からログイン・コマンド実行・削除まで一度通して試します。
   CLIでBastionを作れたことや、NSGの設定が正しいことだけでは、ブラウザーでログインできるかは分かりません。
10. 終了後にRG・Bastion・公開IP・ディスクの削除漏れを確認する担当者と、削除に失敗した参加者から引き継ぐ担当者を決めます。

Basicを選んでいるのは、ブラウザー接続と、専用サブネット・公開IPの関係を一緒に見られるためです。
無料のDeveloperは別の構成で、StandardにはPCのSSHクライアントからの接続などが加わります。
費用や検証の都合でプランを変える場合は、別の手順として準備してください。この資料のBasicの手順と混ぜないようにします。

## 自習で見込む時間

| 経過 | 内容 | 必ず確認する点 |
| --- | --- | --- |
| 0〜10分 | 利用先・個人識別名・RG作成 | Microsoftの付与環境、空の自分のRG、Participantタグ |
| 5〜15分 | VNetとサブネット | VM区画とAzureBastionSubnet、/26 |
| 15〜30分 | VM作成と鍵保存 | VMの公開IPなし、RSA、鍵の安全な保存 |
| 30〜40分 | VM側NSGとBastion作成 | 規則300/310、Basic、Standard Static公開IP |
| 40〜55分 | デプロイ待ち・図解の復習 | VMとBastionの状態。待っている間に追加作成しないこと |
| 55〜65分 | Bastion接続・3つのコマンド | Cloud Shellではなく、VM内の`azureuser`で実行しているか |
| 65〜70分 | 切断・割り当て解除 | Bastionは残り、課金が続くこと |
| 70〜85分 | 専用RG削除・残存確認 | VM、Bastion、公開IP、ディスクが削除済み |
| 85〜90分 | 振り返り・引き継ぎ | 接続を確認できていない場合や、削除に失敗した場合は未完了とすること |

座学のあとに75〜90分程度の自習と、予備15分を見込んでもらいます。検証でもBastionの作成・削除には待ち時間がありました。
待ち時間が長くなったら、コマンドの追加やネットワークの補足説明より片付けを優先します。
時間を短くするために、ポートを公開したり大型のSKUへ変更したりはしません。

## 混同しやすい3点

**SSHを使っても、インターネットへ開ける必要はありません。**
VMのパブリック受信ポートは「なし」にし、NSGでBastionサブネットからのTCP 22を許可します。
300で許可し310でほかのSSHを拒否すると、既定のAllowVnetInBoundより先に評価されます。VMサブネットにもNSGがある場合は、NIC側と両方を調べてください。

**公開IPを付けるのはBastionです。**
VMには付けませんが、Basicには必要です。VPNや完全閉域の管理経路と同じ説明にはしないでください。

**接続を切っても、リソースは残ります。**
NSGは通信の規則、SSH鍵はログインの認証です。`exit`はログアウトで、VMの割り当て解除は計算料金を止める操作です。
ディスクなどは削除されず、Bastion Basicも停止で節約できないため、最後はリソースを削除します。

## 再開・途中終了

| 開始時の状態 | 再開する場所・対応 |
| --- | --- |
| VNetだけ作成済み | Task 3から再開します。VMを重複して作らないでください。 |
| VMが作成済みで、RSA鍵がある | Task 6から再開します。 |
| Bastionをデプロイ中 | 完了したか、エラーが出たか確認します。追加のデプロイは行いません。 |
| 鍵がない／Bastion接続に失敗した | 主催者が原因を確認します。時間切れの場合は接続未完了とし、専用RGの削除に進みます。 |
| 接続を確認できた | Task 10から進めます。再起動、更新、外部への通信確認は不要です。 |
| VMは割り当て解除済みで、Bastionが残っている | Task 11〜12の削除に進みます。 |
| リソースを削除中 | 通知と、更新後の一覧で削除の完了を確認します。 |
| 削除に失敗した | 未完了として、削除の担当者と期限を記録します。Bastionの課金が続くため、放置せず引き継いでください。 |

終了時には個人識別名、どこまでできたか、止まったTask、本人による削除結果、迷った画面を記録します。
名前の例は`ksaito73`に統一し、[共通の命名ルール](../self-study.md)を使います。AzureBastionSubnetだけは指定名です。
秘密鍵、IP、実際のリソースID、個人名、加工前の画面は回収しません。
初学者には、手順書だけで試してもらいます。NSGの設定、鍵の選択、Cloud Shellとの取り違えで迷わないかを見てください。
接続していなくてもBasicに料金がかかることと、削除の完了まで待つことが伝わっているかも確認します。
