## 開催前に用意しておくこと

1. 使うサブスクリプション、誰が費用を負担するか、利用期限、参加人数、質問窓口、提出先を決めておきます。
2. 参加者が付与サブスクリプションでRGを新しく作り、自分のリソースを削除できることを確認します。RGは事前に作りません。
3. 必要な範囲のContributor権限などと、組織のポリシーを確認します。参加者全員にOwnerを一律に付与しないでください。
4. Microsoft.Compute、Microsoft.Networkなどのプロバイダー登録と、組織のリージョン・SKU・タグの制約を確認します。
5. 開催用サブスクリプションで、Ubuntu 24.04 x64 Gen2、Standard_D2alds_v6（2 vCPU・4 GiB）、Trusted launch、Standard HDD LRS、高速ネットワーク有効を試します。
   リージョン全体とDaldsv6ファミリーのvCPUクォータに、VM1台あたり2 vCPU×同時参加人数分の余裕があるか、在庫はあるかも別々に調べてください。サービスによってはファミリー名がDaldv6と表示されます。
   SKUが一覧に出ることと、実際にVMを割り当てられることは同じではありません。
6. Standard_D2alds_v6が使えない場合に備え、代替サイズ・リージョンと費用を事前に承認しておきます。参加者が自己判断で大型VMに変更しないよう案内してください。
7. 参加者のPCに秘密鍵を保存できるか、Portalを日本語表示にできるか、ブラウザーとネットワークを利用できるか確認します。
8. VMの時間単価とOSディスクの価格を調べ、人数と待ち時間を含めて費用を見積もります。予備費も確保してください。
   無料枠の適用や請求額は契約によって異なるため、「全員無料」「必ず○円」とは案内しないでください。
9. 開催用のPortalで、作成から停止・RG削除まで一度通して試し、画像を更新します。CLIで確認済みでも、この事前確認は省略しません。
10. 自習の報告に、個人識別名、完了したTask、RGの削除結果を含めます。残存があれば本人に確認し、削除の再開を支援します。

ポリシーによって、バックアップ、Defenderの有料プラン、ログの取り込みなどが自動で付くことがあります。
参加者に解除させず、主催者側で料金と削除時の影響を調べておきます。
Network Watcherが別の共有RGに作られていても、そのRGは削除しないと案内してください。

## 自習で見込む時間

各Taskの時間は余裕を持たせた目安です。作成を待っている間に説明を挟み、全体で60分程度を見込みます。
初めて操作する人や、ネットワークが不安定な場合は75分程度を見込みます。自分で作成・削除する時間も含めて案内します。

| 経過時間 | 内容 | 自分で確かめるポイント |
| --- | --- | --- |
| 0〜5分 | 実習の目的、費用、削除の注意 | 付与サブスクリプションと個人識別名 |
| 5〜12分 | サインイン、自分のRG作成 | RG名とParticipantタグ、空のRGか |
| 12〜25分 | 基本情報、ディスク、ネットワーク | VMサイズ、公開IPなし、公開ポートなし |
| 25〜30分 | レビュー、作成 | 料金と作成前チェック |
| 30〜40分 | デプロイ待ち、概要、RG一覧 | VMが「実行中」か、一緒に何が作られたか |
| 40〜45分 | 停止（割り当て解除） | ディスクなどが残っていること |
| 45〜55分 | 専用RGの削除、一覧の更新と確認 | 削除の受付だけでなく、完了まで確認したか |
| 55〜60分 | 振り返り、未完了の引き継ぎ | 全員のRGが削除されたか |

削除の時間を、最後の余り時間にしないことが重要です。
時間が押したら、追加の説明や起動確認より片付けを優先します。
停止までしか進めなかった人は未完了として、誰がいつRGを削除するか決めておきます。

## 説明するときに気を付けること

「左上」「青いボタン」だけでは、画面が少し違う人が迷います。ボタン名と、選ぶ理由を一緒に伝えてください。
作成画面の全項目を順に解説するより、手順書の設定表を見ながら必要な欄を埋めていく方が進めやすくなります。
作成の直前、停止のあと、RGの削除前には、本人が見直せるチェックを残します。
識別名の例は`ksaito73`です。氏名やメールアドレスを収集せず、[全回共通の命名ルール](../self-study.md)で自分のものを見分けられるようにします。

配布前には、初学者に手順書だけで試してもらいます。迷った場所、自力で戻れたか、かかった時間を記録してください。
公開IPの見落とし、削除が終わったかの判断、料金の理解も見ます。作った本人の所要時間だけでは、初学者に必要な時間は分かりません。

## 未実施・途中再開の扱い

| 開始時の状態 | 再開する場所・対応 |
| --- | --- |
| サインイン・権限・費用の確認ができていない | 未実施として、図解の確認と振り返りのみ行います。VMを作成できたとは記録しません。 |
| 作成画面まで進んだが、まだ作成していない | Task 3から設定値を確認して再開します。 |
| デプロイ中／作成に失敗した | 通知、デプロイの詳細、RGの一覧を確認します。重複作成はせず、作成済みの確認か片付けに進みます。 |
| VMが実行中 | Task 7から再開します。VMへのログインは追加しません。 |
| 停止済み（割り当て解除） | Task 10の専用RGの削除から進めます。 |
| RGを削除中 | Task 11で一覧を更新し、削除の完了を確認します。 |
| RGの削除が完了した | 振り返りのみ行います。VMを作り直す必要はありません。 |

終了時には個人識別名、どこまでできたか、最終確認時刻、未完了の理由を記録します。通常の削除は本人が行い、権限・ロックの問題だけ付与元へ相談します。
アカウント情報、実際のリソースID、IP、秘密鍵などの秘密情報、加工前の画面は回収しません。
